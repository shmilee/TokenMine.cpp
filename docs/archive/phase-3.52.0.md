## ③ demo 相机两个真 bug（用户 11-24 报告，门内复现）

**A. 观众 C 键 = 观众观察面与录制内容的碰撞（用户 3 条面板错误的根）**：
demo 循环的观众 C 与录制的 C 事件**共同**循环 `m_cameraMode`；且
`aimForward()` 的 REPLAY 分支对 ThirdFront 施加 V2-1 前视翻转——**观众 C#2
（正面视角）把 demo 玩家注入交互的射线整体翻转 180°**：下一个容器 RMB 开面板
落空 →「panel is not open」级联（用户 f4528/4553/4578 = P8；门内 C2 复现 =
vsync-on + 用户同款操作，首错同帧 4528；41 条级联）。「第一视角离前面物品很远」
= 观众 C 循环到第三人/正面视角的观感。「旋转很奇怪」= 观众轨道 base+offset
相对式：重拍后玩家持续平滑转身，用户的整个相机被带着转。
**修**：观众 C 移除（demo 相机 = 录制内容；14 支 dmo 扫描：10 支 C 后零交互，
4 支（night/river/palace/…）的 C 后交互 = 录制序列自身，模式由录制 C 重建 =
faithful 回放不受影响）+ **真轨道**（绝对角，首次输入从当前基视角连续初始化，
其后用户独占——文档「自由 orbit」语义终于与实现一致）。
双 Input 隔离实证无泄漏（1× 实速 W-only / mouse-only / 无输入 三跑 f4000 存档
pos/yaw/pitch 全同）。

**B. 热循环（2×/vsync-off）墙钟双击收集误触发**：面板双击收集窗（CRAFT-7
0.3s）与 Space 双击飞窗读 solo 墙钟；dmo 的 50f 同槽左键对（0.83s authored）
在热循环压缩到 0.2s < 0.3s = 收集误触——carry-place-merge 模式在**单格**配方
（木板）结果等价（P5 幸存），在**8 格环**配方（熔炉）= 收集吞掉全部已放格 →
配方静默腐化 → 产出 0 → 下游开炉落空 → 级联（门内 C1 复现 = 2× novsync 无
交互 9 错，P10 静默 + P11 起报错）。**修**：REPLAY 两窗改读 `m_simTime`
（demo-dt 累积 = 速度无关 + 确定性；record/solo-live/net 原样 R2 位级）。
