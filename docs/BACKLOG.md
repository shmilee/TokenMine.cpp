## 执行顺序

1. V4-N = 执行序号（11-04 定案全保留；**V4-1 拆分立项先行**——项目
   最大架构项，立项先做设计定案 + 拆分方案：门框 → 下界世界 → 内容
   三段；实机报障项入 UX 行续编号）。
2. 一任务一 phase，走标准阶段流程（详见 AGENTS.md）。
3. 版本号逐版 bump（v4.0.0 = 首个 4.x 版本；PITS 355 三件套）。
4. **每版发布前必做性能 A/B**（用户硬要求），旧侧 = 上一 release tag 或
   指定 commit。
5. tag/release 政策沿用 2.x 收官定案（v2.10.0 第一批 / **v2.19.0 二批收官
   tag**）；大版本 v4.x 起同款（逐版 tag + GitHub release，里程碑 = 收官
   tag——11-04 收官定案，用户可推翻）。
